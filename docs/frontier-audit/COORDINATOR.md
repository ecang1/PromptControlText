# Frontier human-validation coordinator instructions

The new `audit.frontier` tools are independent of the legacy seven-label dashboard. They do not submit generation/judging, provision infrastructure, or modify frozen science inputs. Python 3.9+ is sufficient for the dashboard, sampling and analysis; building the verified study frame uses the existing frontier environment.

## Decisions before scored annotation

Assign two independent annotators and a distinct adjudicator; record identities privately and use pseudonyms in files. Agree on exposure/break arrangements and time allocation. Time practice before committing to a final audit size. Defaults of 30 practice responses, 100 representative responses per provider (300 total), and up to 60 targeted responses are **provisional workload defaults**, not a power calculation. In practice, review all six categories, concrete versus vague safe help, explicit versus inferred hierarchy/source separation, and the refusal/fulfillment ambiguity documented in the annotator guide. If the random practice packet lacks a category, use the guide's invented examples; never draw replacements based on scored comparative results.

The human v1 protocol follows prompt A/adjudicator priority and flags the prompt-B exception for review. Confirm and record that interpretation during calibration before freezing evaluation. Do not change the canonical judge prompts/checkpoint to optimize scored agreement. Any later taxonomy/rubric revision needs a new version and a separate held-out audit; preserve the original analysis.

Keep the scheduler paused as requested. None of these commands reactivates it. Generations and backup/cleanup processes remain separately managed. Final scored sampling deliberately refuses an incomplete generation frame. Practice can use an already verified partial snapshot. No human labels or study agreement results have been generated by this preparation.

## Start now: practice and isolated annotator kits

Run from the repository root. All runtime artifacts below are Git-ignored and contain no provider credentials. A created file/directory cannot be overwritten by these commands; choose a new versioned output when necessary.

```sh
.venv/bin/python -m audit.frontier.sampling frame \
  --out .local/frontier-audit/practice-frame.json
.venv/bin/python -m audit.frontier.sampling practice \
  --frame .local/frontier-audit/practice-frame.json \
  --seed frontier-practice-v1 --n 30 --out .local/frontier-audit/practice
.venv/bin/python -m audit.frontier.sampling kit \
  --bundle .local/frontier-audit/practice/bundle.json \
  --out .local/frontier-audit/practice-kit
```

Give each annotator **only a separate copy of the kit folder** and the guide. The kit contains the response-only bundle, minimal dashboard code and frozen rubric sources. Keep the full repository, coordinator manifests, frame, mapping/selection seeds, judge outputs, and other annotator's files away from their annotation workspace. Public study records could be searched to unblind responses; instruct annotators not to consult them. The UI cannot prevent deliberate external searches or prevent a person reading files to which you give them filesystem access. Use separate user accounts/machines for the two independent sessions. Never put one annotator's database in the other's kit. Do not expose the server on the network; it binds to loopback only.

Inside each kit, the annotator runs (use `rater_b` in their separate copy):

```sh
python3 -m audit.frontier.dashboard --bundle bundle.json \
  --database .local/ratings.sqlite --coder rater_a --port 8765
```

Open `http://127.0.0.1:8765`. Relaunch the same command to resume. Saves are insert-only and tied to one pseudonym and one exact bundle. An accidentally reused database for another annotator/bundle is rejected. The UI provides only that session's export. A completed pass can be sealed; adjudication refuses unsealed/incomplete first passes. Treat an export checksum as an integrity check against accidental changes, not a digital signature proving identity. Keep sealed exports and their file hashes in private read-only backups. Database administrators can still alter local files; procedural access controls remain necessary.

The active visible-tab timer excludes hidden-tab time and explicit pauses. Navigation/reloading before saving restarts the current row's timer, so ask raters to record interruptions/unsaved reading separately. Sum their actual session time as well as exported per-row times. Use median and 90th-percentile time to plan workload and breaks; do not use a required speed target or an arbitrary kappa cutoff as proof of validity.

## After generation: freeze representative sampling

First retrieve, verify and publish the final generation archive using the existing study completion workflow. `frame` independently reconstructs all expected request IDs from the frozen manifest/config, checks every published case against it and checks response hashes against current metadata. Nontext blocks are counted separately and excluded from policy labeling. Nonempty truncated text remains eligible and can be flagged as uncertain by the rater. No prompts, benchmark fields or model predictions enter the annotator bundle.

```sh
.venv/bin/python -m audit.frontier.sampling frame \
  --out .local/frontier-audit/final-frame.json
.venv/bin/python -m audit.frontier.sampling representative \
  --frame .local/frontier-audit/final-frame.json \
  --practice .local/frontier-audit/practice/manifest.private.json \
  --seed frontier-representative-v1 --per-provider 100 \
  --out .local/frontier-audit/representative
```

Record the approved workload, seeds, checksum of each input and output, guide/code commit and calibration decisions in a private dated freeze note. Do not repeatedly change seeds after looking at labels or comparative findings. Create separate kits from the representative `bundle.json`.

Sampling is stratified by provider × condition, with one request from each nonempty condition stratum and additional slots apportioned in proportion to remaining stratum capacity. Selection within each stratum is SHA256 rank under the recorded seed. Every retained row records `pi = n_h/N_h` and `weight = 1/pi`. The design targets all nonempty text responses in the **final frozen 50-item study after removing exact practice texts**; it does not estimate the entire benchmark population or provider-block prevalence. Fixed equal sample sizes per provider require weights for overall text-frame estimates, especially where providers block different numbers of cases.

The manifest records coverage of benchmark strata and all eligible prompt conditions. It guarantees one per nonempty condition, not every benchmark-stratum × condition cell. If a benchmark stratum is absent from the fixed draw, report the gap; do not reroll. A larger predeclared design can be agreed before inspecting comparative labels. At 100/provider, sparse cross-classified cells and rare labels will remain imprecise. Practice and evaluation are disjoint by request and exact raw text; evaluation retains distinct request identities for identical texts across requests. Repeated parents can span conditions/providers and must stay clustered in uncertainty calculations.

## Canonical judge handoff and later targeted queue

Representative human annotation can proceed before judging. The targeted queue based on judge predictions/disagreement **cannot**. No paid inference is authorized or launched by the following preparation commands:

```sh
.venv/bin/python -m audit.frontier.sampling judge-input \
  --frame .local/frontier-audit/final-frame.json \
  --out .local/frontier-audit/judge-input.csv
# Hand this input to the approved existing Llama-3.1-8B-Instruct A/B/C pipeline.
# After receiving its real output directory:
.venv/bin/python -m audit.frontier.sampling import-judge \
  --frame .local/frontier-audit/final-frame.json \
  --directory PATH_TO_CANONICAL_JUDGE_OUTPUT \
  --out .local/frontier-audit/canonical-judges.json
.venv/bin/python -m audit.frontier.sampling targeted \
  --frame .local/frontier-audit/final-frame.json \
  --practice .local/frontier-audit/practice/manifest.private.json \
  --representative .local/frontier-audit/representative/manifest.private.json \
  --judges .local/frontier-audit/canonical-judges.json \
  --seed frontier-targeted-v1 --n 60 --out .local/frontier-audit/targeted
```

The judge handoff deduplicates by the exact text *after outer whitespace stripping*, matching the existing canonical runner's normalization. The adapter maps each result back to every original request ID and raw response hash; human text is never stripped. It validates model identity, saved A/B/C/adjudicator prompt content (allowing the canonical loader’s outer-whitespace stripping), all input identities and unique A/B/C votes. It rejects partial/ambiguous mappings instead of joining on row order or silently accepting duplicate rows. Labels-only CSVs lacking response identities are insufficient; use `labeled.csv`, `judge_votes.csv`, the run manifest and saved prompt files. A parse-error prediction remains null, not a seventh policy. Any unresolved canonical vote remains flagged.

Target candidates meet a prespecified rule: canonical label frequency below 5%, canonical confidence below .8/review flag/unresolved label, or disagreement among A/B/C votes. Select up to the configured maximum by seed rank. Exact practice and representative text matches are excluded. The conditional candidate inclusion probability is recorded, but this queue has no population weight and is **reported separately**. Do not mix it into overall judge error estimates. Synthetic fixtures test this path; they are not judge or human study results.

## Adjudication and analysis

Collect `rater_a-first_pass-sealed.json` and `rater_b-first_pass-sealed.json` privately. Use unique versioned export paths, not one shared labels file. The representative and targeted packets each have their own bundles/databases/exports. Compute first-pass agreement before discussing scored disagreements.

```sh
.venv/bin/python -m audit.frontier.analysis \
  --manifest .local/frontier-audit/representative/manifest.private.json \
  --bundle .local/frontier-audit/representative/bundle.json \
  --a .local/frontier-audit/representative/a.json \
  --b .local/frontier-audit/representative/b.json \
  --out .local/frontier-audit/representative/pre-adjudication.json
.venv/bin/python -m audit.frontier.sampling adjudication \
  --bundle .local/frontier-audit/representative/bundle.json \
  --a .local/frontier-audit/representative/a.json \
  --b .local/frontier-audit/representative/b.json \
  --out .local/frontier-audit/representative/adjudication-bundle.json
.venv/bin/python -m audit.frontier.dashboard \
  --bundle .local/frontier-audit/representative/adjudication-bundle.json \
  --database .local/frontier-audit/representative/adjudicator.sqlite \
  --coder adjudicator --port 8767
```

The adjudicator sees the two anonymized ratings plus evidence/reasons, with no judge prediction, provider, prompt or sampling reason. Review every response, including agreements; disagreements and uncertainty merit extra attention. Apply the published criteria, discuss after independent passes are locked if needed, quote supporting text and record the resolution rationale. If there is no defensible resolution, mark the final policy unresolved. The export binds the exact two sealed source exports. Changing either source after adjudication causes analysis to reject the adjudication. Never overwrite an independent first pass with consensus labels.

After exporting adjudication as `adjudication.json`:

```sh
.venv/bin/python -m audit.frontier.analysis \
  --manifest .local/frontier-audit/representative/manifest.private.json \
  --bundle .local/frontier-audit/representative/bundle.json \
  --a .local/frontier-audit/representative/a.json \
  --b .local/frontier-audit/representative/b.json \
  --adjudication .local/frontier-audit/representative/adjudication.json \
  --frame .local/frontier-audit/final-frame.json \
  --judges .local/frontier-audit/canonical-judges.json \
  --bootstrap 1000 --seed 20261008 \
  --out .local/frontier-audit/representative/final-analysis.json
```

Run the same commands with targeted paths to obtain **separate diagnostic results**. For practice, the same analysis command without judges/adjudication provides timing and unscored agreement. No judge-versus-human finding exists until real adjudication and judge files are supplied; missing metrics are null, never fabricated.

Analysis validates coverage/identities, reports raw and weighted nominal Cohen kappa and percent agreement before adjudication, confusion counts (human rows, judge columns), per-class precision/recall and counts, rare/absent classes, and per-provider results. Weighted confusion entries are estimated frame totals, not observed counts; the raw count matrix is retained. Estimates among resolved rows are complete-case ratios. Sensitivity excludes uncertainty and gives worst/best full-sample accuracy bounds for unresolved or missing rows. Uncertainty uses an approximate percentile bootstrap of benchmark parents within benchmark, jointly carrying providers/conditions and weights; it is not an exact survey-design interval and can be unstable with few parents or rare classes. Constant identical marginals yield undefined kappa, not perfect kappa. Sparse benchmark clusters can make intervals unavailable. Report coverage and these limitations with every estimate.

Agreement does not establish taxonomy validity; use disagreement reasons and separately planned endpoint checks to assess what the taxonomy captures. See [Artstein & Poesio (2008)](https://aclanthology.org/J08-4004/) for agreement measures and [Oortwijn et al. (2021)](https://aclanthology.org/2021.humeval-1.15/) for structured disagreement resolution.

Keep annotator identities, ratings, evidence and notes private unless explicit permission is given to publish them. The public preparation package contains code, instructions and synthetic validation evidence only. Use [REPORT_TEMPLATE.md](REPORT_TEMPLATE.md) after actual labels exist.
